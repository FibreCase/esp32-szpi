# 第五阶段任务：应用 UI 组件与 Linux 模拟器

状态：规划，尚未实现。日期：2026-10-08。

## 目标与范围

将新的应用 UI 放入 `components/szpi_ui`，替换当前硬件测试用 LVGL 页面；建立 Linux 原生模拟器，使开发板与电脑编译同一套页面、主题、字体和图片源码。沿用 LVGL 9.5.0，不在本任务升级依赖。逻辑分辨率为 320×240。

本阶段首先建立可运行的组件与预览闭环，再按用户确定的产品页面实现新 UI。首页内容、导航形式、视觉风格和具体业务入口尚未确定，不直接将现有硬件测试页当作正式产品设计。降噪、音频实时队列、OTA、蓝牙、原生 USB 及新增硬件驱动不在本阶段范围。

## 职责与依赖

| 模块 | 职责 |
| --- | --- |
| szpi_ui | 页面对象、导航、主题、资源、交互事件和状态展示 |
| szpi_app | 应用流程、运行状态、服务调度；转换 UI 状态并执行请求 |
| szpi_display / szpi_input | 开发板显示、触摸及硬件输入适配 |
| simulator | SDL 窗口、鼠标键盘、时间来源、模拟状态和请求响应 |

新增依赖方向为 `szpi_app -> szpi_ui -> LVGL`；已有外设依赖方向保持。禁止 `szpi_ui` 反向依赖 `szpi_app` 或外设组件。共享 UI 源码及公共头不包含 ESP-IDF、FreeRTOS、GPIO 或驱动头文件，仅使用标准 C 与必要的 LVGL 类型。

`szpi_ui` 不创建任务，不安装显示或输入驱动，不拥有共享总线。板上继续由 runtime 创建的唯一 UI 任务执行全部 LVGL 操作；Linux 由主循环执行。已有 `ui_service.c` 保留板上初始化、调度、输入轮询和停止协调职责。

实施时同步修改 AGENTS.md、code_architecture.md 和 README，将原有“页面属于 szpi_app”的规范调整为“页面属于 szpi_ui，业务流程属于 szpi_app”。本任务文档仅描述目标，不表示该架构已落地。

## UI 契约与生命周期

- 提供创建、更新状态和销毁接口，明确调用线程、重复调用规则和资源所有权。共享接口使用普通 C 类型；需要返回状态时使用 UI 自有结果类型，由板上适配转换为 esp_err_t。
- 使用类型明确的状态快照和操作回调；不建立通用事件总线、插件框架或全局服务句柄仓库。
- szpi_app 把服务状态转换为 UI 模型，UI 不调用设备查询函数、不加服务 mutex。快照中的字符串必须复制或明确有效期，不能保存短生命周期指针。
- 点击回调仅提交操作请求，例如开始录音、停止、调整音量；板上桥接调用已有有界服务队列，并将拒绝、忙碌和失败反馈到 UI。不得在 LVGL 回调中等待设备、执行文件 I/O、格式化或网络操作。
- 状态更新按实际变化刷新控件，避免每轮重建页面。页面退出时清理其 timer、动画及回调引用，防止对已删除对象更新。
- 现有相机 framebuffer / staging 所有权保持。UI 仅在约定有效期内借用图像数据；切页或停止时先停止生产，解绑图像并等待刷新 / DMA 完成后再释放缓冲。Linux 模拟帧也遵循相同借用契约。
- BOOT 的语义事件由 app 转换后送入 UI；触摸坐标映射留在板上输入层。模拟器鼠标坐标对应逻辑分辨率，键盘映射为模拟 BOOT 事件。
- 若正式 UI 保留格式化能力，必须继续采用二次确认及当前 generation 校验，不能绕过 storage 服务安全入口。模拟器格式化只改变模拟状态，不操作宿主磁盘或真实 SD 卡。

## Linux 模拟器

采用 LVGL 官方 SDL2 驱动、原生 GCC 与 CMake。建立独立桌面可执行程序，不模拟 ESP32 指令集，不编译固件 runtime 或外设驱动。

- LVGL 固定为与板上一致的 9.5.0；依赖来源和版本可复现，不跟随 master。独立获取官方源码，不依赖或修改 IDF 生成的 managed_components。
- 实施前检查本机 CMake、编译器、SDL2 开发包；按实际 Linux 发行版记录安装方式。普通构建与运行不得要求 root。
- 两端对齐颜色深度、字体、主题、布局、断言及页面使用的 LVGL 功能。SDL 驱动、时间来源等平台差异保留在模拟器配置。记录内存配置差异，不能用桌面充足内存掩盖板上预算。
- 模拟器窗口固定 320×240、1:1 显示且不可调整大小；鼠标模拟触摸，键盘模拟 BOOT。
- mock_backend 支持可重复的正常、处理中、失败场景：Wi-Fi 离线 / 联网、无卡 / FAT32 就绪 / 卡满、录音 / 回放 / 失败，以及输入和预览演示。仅实现已存在页面所需场景。
- 相机优先用固定测试图或生成帧，不依赖电脑摄像头；音频先模拟状态和声级，不默认接入宿主麦克风或扬声器。
- LVGL tick 使用单调时间；主循环有等待，不忙等。退出时销毁 UI 和 SDL 资源。

预期使用入口（实施后核实并写入 README）：

```sh
cmake -S simulator -B simulator/build
cmake --build simulator/build
./simulator/build/szpi_ui_sim
```

参考：[LVGL 9.5 SDL 驱动](https://lvgl.io/docs/open/9.5/integration/pc/sdl.html)、[官方 PC CMake 示例](https://github.com/lvgl/lv_port_pc_vscode)。示例用于参考启动与构建，不直接使用其未锁定的依赖版本。

## 实施顺序

1. 梳理旧 ui_pages 与 app 的直接耦合，确定最小 UI 状态、请求和生命周期契约。
2. 建立 szpi_ui 与 Linux 模拟器，用一个最小页面验证共享源码、点击和状态更新；板上保持原有 runtime 和显示输入适配。
3. 明确产品页面与交互，建立公共主题及资源，再实现正式页面。UI 文案使用英文，统一使用 Noto Sans；字体仅嵌入实际需要的 ASCII 字形，并记录生成方法及字体许可。
4. 在 szpi_app 接入状态转换和操作桥接，逐项验证请求成功、拒绝、故障和停止流程。
5. 新 UI 完成双端验证后移除旧测试页面及其专用状态 / 入口；硬件服务、资源诊断与故障能力保留。需要继续保留的诊断页由用户确定，不默认全部移植。
6. 更新架构、使用说明及阶段验收记录，标明模拟器验证和板上验证的区别。

## 验收标准

- [ ] 相同页面源码在 Linux 和 ESP32-S3 编译运行，共享页面没有平台条件分支及硬件头依赖。
- [ ] 模拟器可独立于 ESP-IDF 构建；全新构建目录能复现固定 LVGL 版本。
- [ ] 320×240 布局、字体、图像、颜色及触摸区域双端一致；模拟器窗口固定 1:1 且不可调整大小。
- [ ] IMU X 轴判断正立 / 倒立并自动 180° 旋转；方向切换时触摸坐标同步，阈值滞回稳定。
- [ ] 已实现页面可以模拟正常、忙碌、失败状态；请求拒绝可见，不显示虚假成功。
- [ ] 固件通过 IDF 6.1 增量和独立 defaults 构建；不修改 managed_components，不新增 UI 任务。
- [ ] 反复切页与退出无失效对象访问；按需用主机内存检查工具验证页面生命周期。
- [ ] 相机退出与 UI 停止保持正确缓冲归还及 DMA 完成规则。
- [ ] 板上显示 / 触摸、BOOT 与保留的业务流程正常，记录堆、任务栈和刷新表现。
- [ ] 连续运行 30 分钟及页面切换至少 50 次，未出现持续堆下降、死锁或异常重启。
- [ ] 正式 UI 替换旧测试页；文档、依赖和资源许可记录齐全。

模拟器验收只证明布局、交互及共享 UI 逻辑；实际 SPI 帧率、DMA、触摸手感、I²S、SD 吞吐和并行硬件稳定性必须上板验证。

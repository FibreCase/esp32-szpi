# 第二阶段附加任务：QMI8658A 与 BOOT 按键适配

制定日期：2026-10-07。状态：**实现与主机逻辑测试完成，IDF 6.1 构建通过；上板验证待完成**。

依据：[开发规则](../../AGENTS.md)、[硬件接线](../hardware_io.md)、[代码架构](../code_architecture.md)、[第二阶段任务](task_phase_2.md)。第三阶段用户反馈基本完成，其未执行的量化验收仍按 [第三阶段验证记录](phase_3_validation.md) 保留。

## 1. 目标与范围

在现有 `szpi_input` 内适配 QMI8658A 六轴传感器和 SW2 / BOOT 按键。增加输入验证页，展示有效 IMU 数据、基本倾角及按键事件，保持显示、触摸、camera 预览和 Wi-Fi 可用。

本任务覆盖传感器识别、配置、轮询、单位转换、错误处理，以及 BOOT 按键消抖、短按、长按和释放。暂不做姿态融合、航向角、计步、运动识别、FIFO 连续记录、自动旋转屏幕或按键触发拍照 / 重启 / 擦除。不要把加速度计算的倾角称为完整三维姿态。

## 2. 官方参考与采用方式

主要参考用户指定的 [立创第 5 章：姿态传感器](https://wiki.lckfb.com/zh-hans/szpi-esp32s3/beginner/attitude-sensor.html)。教程给出 WHO_AM_I=0x05、软件复位、寄存器自增、加速度 ±4g / 陀螺仪 ±512dps 和 250Hz 初始配置，以及状态检查和连续读取六轴数据的流程。

实现前结合 [QST QMI8658A 数据手册 Rev A](https://www.qstcorp.com/upload/pdf/202301/13-52-25%20QMI8658A%20Datasheet%20Rev%20A.pdf) 复核寄存器位义、灵敏度、字节顺序及数据就绪机制。不得直接照搬教程中的旧 I²C API、无限等待 ID、忽略读写返回值或单纯按任一 ready bit 就发布成对六轴新样本的处理。

优先评估现成驱动是否支持 QMI8658A、IDF 6.1 新 I²C、借用总线和可控清理。若不合适，按教程和手册在 input 内实现小范围寄存器驱动，记录选择理由；不新增通用 HAL，不修改 managed_components。若引入依赖，在 input 的 manifest 固定实际验证版本，锁文件由组件管理器生成。

## 3. 硬件与初始参数

| 项目 | 初始配置 / 约束 |
| --- | --- |
| IMU | 板载 U3 QMI8658A，7-bit 地址 0x6A |
| I²C | 借用 board I²C0 / GPIO1、2，100kHz；只创建设备句柄 |
| IMU 中断 | INT1 / INT2 未连接，轮询；不占用新 GPIO |
| 身份 | WHO_AM_I 预期 0x05；记录 revision，不擅自硬编码未核实 revision |
| 加速度 | ±4g，250Hz；按官方起点，位义和实际生效值实施时复核 |
| 陀螺仪 | ±512dps，250Hz；按官方起点，位义和实际生效值实施时复核 |
| 软件读取 | 初始 20ms 一次，读取最新有效样本；不宣称无损获取全部 250Hz 数据 |
| UI 更新 | 初始 100ms 一次，控件持久创建，只更新数据 |
| I²C 超时 | 单次事务初始 5ms；初始化最多 3 次身份探测，无无限重试 |
| BOOT | SW2 / GPIO0，低有效、板载 10kΩ 上拉，只作输入 |
| 按键采样 | UI 现有 4ms 循环；不增加 GPIO ISR、timer 或按键任务 |
| 消抖 / 长按 | 初始 20ms / 800ms，按单调时间计算，不按循环次数计时 |

固定 GPIO、地址和有效电平只放 board bindings；量程、轮询周期、阈值按需 CONFIG_SZPI_* 管理，持久默认配置写入 sdkconfig.defaults 并同步实际配置。初始化延时参考教程但需按手册确认。BOOT 属于启动配置脚，运行时输入适配不得驱动 GPIO0 或干扰下载电路；SW1 是硬件复位键，不作为按键适配对象。

## 5. QMI8658A 采集与数据契约

- [x] 有界身份探测，读失败和身份不符分别报告；初始化成功前不记录 READY。
- [x] 按手册执行软件复位、配置量程 / ODR / 自增 / 传感器使能，关键写入检查并读回验证。
- [x] 按 STATUSINT 同步锁定数据后，从 AX_L 开始连续读取六轴数据。
- [x] 明确解析小端有符号 16 位值，不把缓冲强转为 int16_t 指针。
- [x] 输出原始六轴值、加速度 g、角速度 dps、单调时间戳、样本序号、valid / fresh 和读取耗时。
- [x] 未 ready 不是总线故障，不累计为 I²C 错误；不能把上次数据当新样本发布。超过 200ms 无新样本标记 stale。
- [x] 连续 5 次真实读取失败后停止轮询；仅显式重试重新初始化，缺失 IMU 不阻塞 UI / touch / camera。
- [x] 倾角仅作静态验证：使用 atan2 公式；加速度模长偏离静态重力时标记不可靠，不计算 yaw。
- [x] 保留 sensor 原始轴用于排查，不套用 LCD / 触摸坐标变换；实物轴向核对待上板。

## 6. BOOT 按键事件规则

以稳定电平和单调时间实现状态机，事件只在本次读取产生，消费后不重复上报。

1. 原始输入连续保持新状态达到消抖阈值，才切换稳定按下 / 释放状态。
2. 稳定按下产生一次 PRESSED；达到长按阈值产生一次 LONG_PRESS，持续按住不重复。
3. 稳定释放产生一次 RELEASED；若未产生 LONG_PRESS，则产生一次 SHORT_PRESS。长按释放不再产生短按。
4. 启动或服务重新启用时若按键已按住，先等待稳定释放后再接受新按下；初始释放不生成假点击。
5. 停止 / 重新初始化清除计时与待处理事件；不得把上次按住状态带入下次启动。

事件携带时间戳和稳定状态，初始不支持双击或长按连发。初始化时验证 GPIO 配置返回值；适配只读 GPIO0，按键行为先用于验证计数，不隐含任何破坏性动作。

## 7. UI、资源与停止

新增可进入 / 返回的 Input 验证页，显示 WHO_AM_I、六轴原始值和单位值、roll / pitch 静态倾角、fresh / stale / fault、BOOT 状态及短按 / 长按计数。提供显式 IMU Retry，保留返回及亮度操作；UI 使用英文和数字，不引入中文字体。

IMU 初始由同一 UI 任务每 20ms 轮询，BOOT 每轮采样。IMU 只在其启用条件满足时读取，初始化时的复位等待不放在正常刷新路径。记录两次 I²C 事务总耗时和 UI overrun；若 camera + touch + IMU 实测无法维持交互，再由 runtime 创建有实测依据的 input 服务任务，不能先预建任务掩盖阻塞。

资源只有一个借用总线上的 IMU device handle、内部小数据缓冲与消抖状态，无新增 PSRAM 大缓冲。实施时登记所有者、容量、销毁者；不修改 LCD DMA、camera 帧或 staging 所有权。

Stop 由 runtime / UI 生命周期协调：停止新轮询 → 等本次有界 I²C 事务结束 → 适用时关闭 IMU 采集 → 删除自己的设备句柄 → 清除 BOOT 状态 → 确认停止。关闭采集失败必须记录，但已无在途事务时继续释放本次资源；不可删除 board 总线或复位其它设备。
